# Plan traceability

Every recommendation in the [enterprise plan](enterprise-plan.md) (the source document)
and its engineering contract [`ARCHITECTURE.md`](../ARCHITECTURE.md) mapped to the
module, function or template that implements it and the test that proves it. Section
numbers refer to the plan; ARCHITECTURE sections are cited as "A§n".

Status legend — **done**: implemented and covered by the named passing test;
**done (observed)**: additionally exercised by hand in this pass (outputs in the README,
`security.md`, `operations.md`); **partial**: implemented with a documented limitation;
**gap**: recommended by the plan, not implemented.

## Known issues found in this pass

- `aisdlc cost budget-check --budgets FILE` prints a raw pydantic traceback when the file
  does not match the `Budget` shape (`scope_type`/`scope_id`, not `scope`).
- `aisdlc cost report --group-by role` is rejected; the ledger field is `agent_role`.
- `aisdlc plan risk classify` escalates the standard pilot to `ai_agent` because its threat
  model declares a data source (by design of the heuristic; surprising for a pilot whose
  declared class is `standard`).
- `pilots/ai-agent/README.md` omits the required `--target` for `security campaign run`.
- There is no `serve` subcommand; the HTTP API runs via `uvicorn --factory aisdlc.control_plane.server:create_app`.
