---
id: ADR-0001
title: Generate a thin module per form; keep all behaviour in the engine
status: accepted
context: Business users change forms often. Behaviour duplicated into every generated
  file would drift and would have to be re-tested per form.
decision: The generator embeds only the form specification into the generated module
  and delegates validation, cut-off, storage and the CLI to lowcode.app/schema/table.
  The generated file is checked in and an architecture test proves it matches its
  form.
consequences:
- Engine fixes reach every form without regeneration
- Generated modules are trivially small and fully covered by the form's tests
- Regeneration must be deterministic (byte-identical for an unchanged form)
alternatives:
- 'Copy the whole engine into each generated module (rejected: drift, duplicated tests)'
- 'Interpret the form at runtime without generating code (rejected: no per-form import
  surface for automation)'
deciders:
- solution architect
- office manager
---
# ADR-0001

The generated module is an interface, not an implementation.
