---
id: ADR-0001
title: Priority is a closed string vocabulary with an explicit rank
status: accepted
context: Callers want readable values in the JSON store and the CLI, while sorting needs a
  total order. Integers are opaque; free text cannot be ordered.
decision: Store the priority as one of the strings low, normal, high, urgent and keep the
  rank in a single table in tickets.service; validate on every write, never on read paths.
consequences:
- Adding a level is a one-line change to PRIORITIES and its rank
- Legacy rows without the key load as normal (no migration)
- Sorting is a stable sort keyed on the rank (O(n log n))
alternatives:
- 'Integer priority 1..4 (rejected: unreadable in the store and the CLI)'
- 'Free-text priority (rejected: cannot be ordered or validated)'
deciders:
- tickets-lead
---
# ADR-0001

The vocabulary and its order live in one place so the service, the CLI help text and the
contract test cannot drift apart.
