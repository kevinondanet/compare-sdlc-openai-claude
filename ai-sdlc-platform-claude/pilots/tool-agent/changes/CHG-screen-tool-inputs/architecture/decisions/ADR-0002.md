---
id: ADR-0002
title: Tool tiers are enforced by the platform policy enforcer with a rule-based approver
status: accepted
context: The three tools differ in blast radius (read private data, send e-mail, delete a
  record). Approval must not depend on the assistant's own judgement.
decision: assistant.governance generates a governance.toolkit/v1 policy for the
  support-assistant role from the platform tier taxonomy (search tightened to tier 1,
  send_email tier 3 with the recipient-on-file rule as approver, delete_data tier 4 denied)
  and evaluates every tool request through aisdlc.governance.enforce.PolicyEnforcer.
consequences:
- Denials and approvals are audited with tier, rule and approver
- delete_record can never execute from the agent loop; a human runs it out of band
- The policy file can be validated and checked with `aisdlc governance policy …`
alternatives:
- 'Allow-list inside the assistant (rejected: no approvals, no audit chain)'
- 'Human approval for every e-mail (rejected: rule covers the only legitimate recipient)'
deciders:
- assistant-lead
- security
---
